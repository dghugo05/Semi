3. Evaluación de la tarea

FPD - Free Text

Criterios de evaluación implicados

RA1: Genera interfaces gráficos de usuario mediante editores visuales utilizando las funcionalidades del editor y adaptando el código generado.

a) Se han analizado las herramientas y librerías disponibles para la generación de interfaces gráficos.
b) Se ha creado un interfaz gráfico utilizando las herramientas de un editor visual.
c) Se han utilizado las funciones del editor para ubicar los componentes del interfaz.
d) Se han modificado las propiedades de los componentes para adecuarlas a las necesidades de la aplicación.
e) Se ha analizado el código generado por el editor visual.
f) Se ha modificado el código generado por el editor visual.
g) Se han asociado a los eventos las acciones correspondientes.
h) Se ha desarrollado una aplicación que incluye el interfaz gráfico obtenido

¿Cómo valoramos y puntuamos tu tarea?

Criterio RA1 Peso Excelente Bueno Aceptable Deficiente
a) Se han analizado las herramientas y librerías disponibles para la generación de interfaces gráficos. 20% Compara alternativas (Swing/AWT vs. JavaFX), justifica Swing+GUI Builder para JFrame+JDialog en el caso veterinario; explica limitaciones del autogenerado; incluye captura del editor. Identifica GUI Builder y Swing; justifica brevemente la elección con 1 captura. Enumera herramientas sin justificar ni vincular al caso. No identifica herramientas relevantes ni su pertinencia.
b) Creación de la interfaz con el editor visual 20% Construye en el GUI Builder el JFrame (menú, botón, imagen) y el JDialog con todos los campos exigidos. Interfaz casi completa; falta 1 componente menor o etiqueta. Interfaz parcial; faltan 2–3 campos clave o tipos incorrectos. No se evidencia construcción con el editor visual.
c) Ubicación de componentes con funciones del editor 20% Usa layouts con alineaciones consistentes; sin solapes; tamaños preferidos coherentes; etiquetas y campos alineados. Disposición adecuada con leves desalineaciones o espacios irregulares. Distribución poco consistente; alineaciones o tamaños dispares. Ubicación deficiente; superposiciones o fuera de vista.
e) Análisis del código generado por el editor 20% Explica initComponents, secciones protegidas, modelos y layouts; riesgos de editar zonas protegidas y cómo extender fuera de ellas (con fragmento comentado). Describe secciones clave y relación con la UI. Observaciones superficiales sin conexión con la UI. No presenta análisis.
f) Modificación del código generado por el editor 20% Añade validaciones, listeners y utilidades fuera de zonas protegidas; separa UI y lógica; no rompe el autogenerado. Modifica con leves advertencias sin afectar estabilidad. Cambios invasivos/desordenados con warnings frecuentes. Edita zonas protegidas o rompe el código.
